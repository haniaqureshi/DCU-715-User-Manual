## Route Management Troubleshooting 
While managing measurement routes, executing tests, or transferring data within the **Routes** module, users may encounter
validation warnings or communication errors. This section details the error screens, their root causes, and specific
steps to resolve them.

### Error: Stale Route Configuration Data
This alert appears when a selected measurement route contains data that hasn’t been updated for more than 14 days.

<FigureProvider>
    <Figure 
        id="Select-Route-Warning-Dialogbox" 
        src="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Select-Route-Warning-Dialogbox-Light.jpg"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Select-Route-Warning-Dialogbox-Dark.jpg" 
        caption="Select Route Warning Dialogbox" 
        width="50%"
    />
</FigureProvider>

:::warning

Routes older than two weeks may not contain the latest equipment changes, updated limits, or measurement point updates. 
Therefore, their use is not recommended.

:::

#### Root Cause

The active route file stored locally on the device was synchronized with the server more than two weeks (14 days) ago. 
The system flags this to prevent technicians from collecting data against outdated machinery configurations or threshold parameters.

#### Possible Troubleshooting Steps

- **Acknowledge and proceed temporarily:**

    <ul>
        <li>If you must collect data immediately and are certain no plant modifications occurred, click **YES** on 
        the dialog box to acknowledge the warning and continue using the existing configuration.</li>
        <li>Alternatively, click **NO** to disregard the alert, dismiss the dialog, and proceed straight to the active
        asset list.</li>
    </ul>

- **Synchronize with the server (Recommended):**

    <ul>
        <li>Exit the measurement sequence and navigate back to the main menu.</li>
        <li>Open **Update Routes** and establish a stable connection to download the latest route modifications.</li>
    </ul>

### Error: Missing Plot Measurement Data
This warning pop-up displays when an operator attempts to access the graphic visualization or trend plot for a measurement point that does not contain any recorded vibration history.

:::warning

No measurement data for: Account: 1289, Measurement nr: 0

:::

<FigureProvider>
    <Figure 
        id="Plot-Screen-Error-Message" 
        src="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Plot-Screen-Error-Message-Light.jpg"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Plot-Screen-Error-Message-Dark.jpg" 
        caption="Plot Screen Error Message" 
        width="50%"
    />
</FigureProvider>

#### Root Cause

The Route Management system has successfully loaded the measurement point configuration (Meas. Point: 682052, Mode: Spectrum), 
but no actual readings have been saved for this specific asset account yet. Because the X, Y, and Z values are entirely zero ($0.000$), 
the system cannot generate a graphical spectral curve or time-domain waveform.

#### Possible Troubleshooting Steps

- **Take a live measurement:**
    <ul><li>Click the **Close** button to exit the warning modal and return to the primary navigation interface.</li>
    <li>Ensure the physical sensor is properly mounted on the machine asset, then click **Measure** from the side operational panel to record fresh data.</li>
    <li>Once the live collection completes, re-enter the **Plot** view via the **More** screen.</li></ul>

- **Verify database sync status:**
    <ul><li>If the measurements were taken previously or by another technician, the data might not be loaded locally. Navigate to Update Routes to trigger a server 
    request and pull the latest synchronized asset database files into your device.</li></ul>


### Error: Multi-Axis Sensor Conflict on Waterfall Measurement
This error displays as a warning pop-up when attempting to configure a Waterfall measurement layout while an incompatible multi-axis hardware profile is selected.

<FigureProvider>
    <Figure 
        id="Add-Points-Waterfall-Measurement-Error-Message" 
        src="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Add-Points-Waterfall-Measurement-Error-Message-Light.jpg"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Add-Points-Waterfall-Measurement-Error-Message-Dark.jpg" 
        caption="Add Points Waterfall Measurement Error Message" 
        width="50%"
    />
</FigureProvider>

:::warning

A single axis sensor must be selected. Channel Z must be selected.

:::

#### Root Cause

The Waterfall measurement type within the DCU software architecture does not support triaxial or multi-channel acquisition settings.
It requires a dedicated single-axis hardware sensor configuration locked explicitly to Channel Z.

#### Possible Troubleshooting Steps

- **Modify the active sensor configuration:**
        <ul>
            <li>Dismiss the warning by clicking **Close**.</li>
            <li>On the right-hand panel, click the **Sensor** button to open the Sensor Type dialog box.</li>
            <li>Change the Sensor Type and Sensitivity dropdown options to match a single-axis specification.</li>
            <li>Ensure your channel assignment is locked to **Channel Z**, then click **Ok** to save the hardware profile. </li>
        </ul>
- **Verify hardware attachment:**
    <ul>
        <li>Ensure that the physical cable matching your single-axis accelerometer is connected to the correct channel input 
        port on the DCU framework before starting the test.</li>
    </ul>

### Error: Missing Measurement Point ID Number
This warning appears on the Add New Point module screen when a user attempts to save a custom measurement configuration without providing an identifier.

<FigureProvider>

:::warning

The Meas Point ID cannot be empty. Enter 6 digits Measure Point ID.

:::

#### Root Cause

The software database requires a mandatory unique 6-digit identification string to index and store new or custom measurement points in the SQL Server database schema.

#### Possible Troubleshooting Steps

- **Input a valid identification string:**
    <ul>
        <li>Click **Close** to dismiss the warning box. The numerical pin-pad dialog overlay will automatically open.</li>
        <li>Type a valid **6-digit** numeric string into the keypad.</li>
        <li>Verify that the green status message **"Valid value"** appears, which unlocks the **Ok** action button.</li>
        <li>Click **Ok** to apply the ID entry.</li>
    </ul>

### Error: Parameter Shift Based on ID Rule
This notification displays as an informational warning box immediately following a successful manual ID validation entry.

<FigureProvider>
    <Figure 
        id="Add-Points-Frequency-Change-Error-Message" 
        src="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Add-Points-Frequency-Change-Error-Message-Light.jpg"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Add-Points-Frequency-Change-Error-Message-Dark.jpg" 
        caption="Add Points Frequency Change Error Message" 
        width="50%"
    />
</FigureProvider>

:::warning

Frequency Changed based on ID number.

:::

#### Root Cause

The DCU software features built-in automation rules that automatically link specific equipment types and diagnostic 
frequencies to defined ID number blocks. When a matching 6-digit ID is validated, the application automatically overwrites 
the current frequency limits to guarantee compliant data logging.

#### Possible Troubleshooting Steps

- **Review point parameters:**
    - Click Close to accept the automated shift and clear the message box.
    - Before proceeding to collect data, navigate to More > Display Parameters from the side panel.
    - Verify that the updated frequency limits (e.g., 250,000 CPM) and diagnostic parameters match your targeted 
        asset's field conditions.

### Error: Measurement Point ID Search Failure
This error dialog displays on the screen when an operator uses the quick-access shortcut tool to search for an asset profile, but the entered ID does not return a match.

<FigureProvider>
    <Figure 
        id="Add-Points-ID-Not-Found-Error-Message" 
        src="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Add-Points-ID-Not-Found-Error-Message-Light.jpg"

        caption="Add Points ID Not Found Error Message" 
        width="50%"
    />
</FigureProvider>

:::warning

Point ID Could Not Find in Measurement.

:::

#### Root Cause

The 6-digit identification string entered on the numeric pin-pad shortcut screen does not exist within the active route file currently loaded into the local memory of the DCU device.

#### Possible Troubleshooting Steps

- **Check ID accuracy:**
    - Verify the physical asset tag on the machine to ensure you didn't mistype the 6 digits.
    - Re-enter the unique ID string carefully via the **Add ID** layout interface.
- **Verify route inclusion:**
    - If the ID is correct but continues to fail, check if the specific asset belongs to a completely different operational area or plant route file.
    - Load the correct route asset package via **Measurements > Select Route** or update the device database files through the server update channel.

### Error: No Route Selected for Deletion
This error or warning dialog appears when a user clicks the Delete action button without first highlighting or selecting any route from the available list.

<FigureProvider>
    <Figure 
        id="Delete-Route-Error-Message" 
        src="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Delete-Route-Error-Message-Light.jpg"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/1-Routes/Delete-Route-Error-Message-Dark.jpg" 
        caption="Delete Route Error Message" 
        width="50%"
    />
</FigureProvider>

:::warning

Point ID Could Not Find in Measurement.

:::

#### Root Cause

The DCU software requires an active selection checkbox or highlighted row index to execute a deletion command from the local SQL Server database.
If the command is triggered while the selection state is empty, the operation is blocked to prevent database errors.

#### Possible Troubleshooting Steps

- **Select a Route:**
    - Dismiss the warning dialog box by clicking **Close**.
    - Look at the route list grid and tap directly on the route profile you wish to remove to highlight it (or check the box in the selection column).
    - Once the row is active, click the **Delete** button again from the operational menu.
- **Refresh the Route List:**
    - If the list appears completely blank and you cannot select anything, it means no routes are currently stored locally on the device.
    - If you need to clear space or reset the view, use the **Update Routes** menu to sync with the server and refresh your local asset tracking list.

## Measurement Troubleshooting 

While transmitting measurement data, exporting reports, managing customer reports, or deleting measurement records, users may encounter validation warnings dialogs.
This section explains the possible causes of these messages and provides recommended troubleshooting steps. 

### Error: No Route Selected for Transmission 

This warning dialog appears when the **Transmit** button is selected without choosing any route for transmission.

## Special Test Troubleshooting
### Error: Route Configuration is More Than Two Weeks Old
This warning dialog appears on the **Bump Test – Select Route** screen when the user selects a route that has not been
updated for more than two weeks before starting a **Bump Test**.

<FigureProvider>
    <Figure 
        id="Bump-Test-(Route-Age-Warning-Dialog)" 
        src="/img/Appendix/Appendix B-Troubleshooting/3-SpecialTests/Bump-Test-(Route-Age-Warning-Dialog)-Light.jpg"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/3-SpecialTests/Bump-Test-(Route-Age-Warning-Dialog)-Dark.jpg" 
        caption="Bump Test (Route Age Warning Dialog)" 
        width="50%"
    />
</FigureProvider>

:::warning

The route is more than 2 weeks old. Please download a new route before proceeding! Press **'Yes'** to exit and download
a new ROUTE or **'No'** to proceed with the old **ROUTE**.

:::

#### Root Cause
The selected route has not been synchronized with the DCMS server for more than 14 days. As a result, the route may
not contain the latest machine information, updated measurement points, or current test parameters required for the
Bump Test.

#### Possible Troubleshooting Steps
- Select **Yes** to exit the current screen and download the latest route from the server (recommended).
- Ensure the DCU is connected to the network before updating the route.
- After updating the route, reopen the **Bump Test** module and select the updated route.
- If an updated route is not available and you are certain that no changes have been made to the route configuration,
    select **No** to continue using the existing route.
This version matches the style and level of detail used in your Chapter 3 troubleshooting section while referring
specifically to the **Bump Test** module.

## DCU Setup TroubleShooting

While working in **DCU Setup**, the user might come across errors while performing certain actions. In this section, 
the user will see the errors associated with DCU Setup along with the remediation steps.

### Error: The update file could not be downloaded from the CMAS server 
This error may appear while upgrading the DCU software using the ITR.com via CMAS option.

:::note

CMAS is another ITR system that can exchange data with the DCU. The CMAS system uses OPC for communication.

:::

<FigureProvider>
    <Figure 
        id="CMAS-Update-Download-Error" 
        src="/img/Appendix/Appendix B-Troubleshooting/4-DCUSetup/CMAS-Update-Download-Error-Light.png"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/4-DCUSetup/CMAS-Update-Download-Error-Dark.png" 
        caption="CMAS update download error" 
        width="50%"
    />
</FigureProvider>

#### Root Cause
The DCU cannot download the update file from the CMAS server. This may happen if the DCU cannot reach the CMAS 
server, the network connection is unavailable or unstable, the CMAS server is not responding, or the update file
is not available from the selected source.

#### Possible Troubleshooting Steps

1. Check the network connection:
    a. Confirm that the DCU has an active internet connection.
    b. Run **Internet Test** from the **Maintenance** submenu to verify connectivity.
2. Check CMAS availability:
    a. Confirm that the CMAS server is online and reachable from the DCU network.
    b. If the server is unavailable, wait until the connection is restored and try the upgrade again.
3. Review the log file:
    a. Check the DCU log for more information about the failed download.
    b. **Action Required:** Resolve the issue shown in the log, and then run the software upgrade again.
4. Contact support:
    a. If the error continues after completing the checks above, contact the system administrator or ITR support.

### Error: The touch screen has not been tested properly
This error may appear when the user exits the **Touchscreen Test** screen without testing the touchscreen.

<FigureProvider>
    <Figure 
        id="Touchscreen-Test-Warning-Dialog-Box" 
        src="/img/Appendix/Appendix B-Troubleshooting/4-DCUSetup/Touchscreen-Test-Warning-Dialog-Box-Light.png.png"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/4-DCUSetup/Touchscreen-Test-Warning-Dialog-Box-Dark.png.png" 
        caption="Touchscreen test warning dialog box " 
        width="50%"
    />
</FigureProvider>

#### Root Cause 
The DCU did not detect touch input before the user exited the **Touchscreen Test** screen. This can happen if the 
user selects **Close** without touching, tapping, or swiping across the touchscreen.

#### Possible Troubleshooting Steps
1. Run the touchscreen test again:
    a. Return to **DCU Setup > Maintenance**.
    b. Select **Touchscreen Test.**
2. Test the touchscreen before exiting:
    a. Touch, tap, or swipe different areas of the touchscreen with your finger.
    b. Test the center, corners, and edges of the display.
3. Exit the test correctly:
    a. Double-tap the **Double tap to exit** box.
    b. Confirm that the message **The touch screen is working properly** appears.
4. Repeat the test if required:
    a. If the warning appears again, repeat the test and make sure the screen shows touch paths before exiting.

#### Action Required
If the touchscreen does not detect finger input after repeated attempts, contact the system administrator or ITR support.

### Error: No signal
This error may appear when the DCU cannot detect a valid tachometer signal during the Tachometer Test.

<FigureProvider>
    <Figure 
        id="Tachometer-Test-No-Signal-Condition" 
        src="/img/Appendix/Appendix B-Troubleshooting/4-DCUSetup/Tachometer-Test-No-Signal-Condition-Light.png"
        srcDark="/img/Appendix/Appendix B-Troubleshooting/4-DCUSetup/Tachometer-Test-No-Signal-Condition-Dark.png" 
        caption="Tachometer Test No signal condition" 
        width="50%"
    />
</FigureProvider>

#### Root Cause
The DCU is not receiving a valid pulse signal from the tachometer sensor. This can occur when the sensor is 
disconnected, improperly positioned, connected to the wrong input, or when the monitored equipment is not 
generating a detectable speed signal.

#### Possible Troubleshooting Steps
1. **Verify the tachometer sensor connection:**
    <ul>
        <li>Confirm that the tachometer sensor is securely connected to the DCU.</li>
        <li>Check that the connector is fully seated.</li>
    </ul>
2. **Inspect the sensor cable:**
    <ul>
        <li>Examine the cable for cuts, bends, loose connections, or other visible damage.</li>
        <li>Replace the cable if damage is suspected.</li>
    </ul>
3. **Verify sensor positioning:**
    <ul>
        <li>Ensure that the tachometer sensor is correctly aligned with the target.</li>
        <li>Confirm that the sensor is within the recommended operating distance.</li>
    </ul>
4. **Verify equipment operation:**
    <ul>
        <li>Confirm that the monitored equipment is running.</li>
        <li>Ensure that the rotating component is producing a measurable speed signal.</li>
    </ul>
5. **Check the selected measurement unit:**
    <ul>
        <li>Switch between **Hertz** and **CPM (Cycles Per Minute)** if necessary.</li>
        <li>Verify that the signal is still not detected.</li>
    </ul>
6. **Repeat the tachometer test:**
    <ul>
        <li>Close the Tachometer Test modal.</li>
        <li>Reopen **DCU Setup > Diagnostics > Tachometer Tests.**</li>
        <li>Allow the DCU 1 to 2 seconds to stabilize the measurement.</li>
    </ul>

#### Action Required:
If the No signal condition remains after verifying the sensor connection, cable condition, sensor positioning, 
and equipment operation, contact the system administrator or ITR support for further assistance.
